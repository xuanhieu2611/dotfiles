A normal day in Neovim.

Open a TypeScript or Python project, read some code, make a change, and save. Here's how your setup helps.

Two modes: i to type, Esc to stop typing and use shortcuts. Unless noted, start shortcuts after pressing Esc.

Reading the keys: Space f means tap Space, then f. Ctrl n means hold Control and press n, not Command. A command like :w needs Enter.

Open the file you need

In your terminal, go to your project's root folder and run nvim. Your file picker and project search start from there.

  1. Press Space f and type part of the filename.
  2. Use Ctrl n / Ctrl p to choose a result, then Enter to open it. Arrow keys work too.

Know the text but not the filename? Use Space s to search across the project. Already opened the file? Space b switches between open files.

In the picker, Ctrl+c cancels while you're typing. Esc switches out of typing mode; another Esc closes it.

Want a small example to follow?

In an existing project, create a disposable file with the example below. You can open a new file directly from the shell:

TypeScript

nvim nvim-practice.ts

Press i, type or paste this, then press Esc:

function greet(name: string): string {
  return "Hello, " + name;
}

console.log(greet("Hieu"));

Python

nvim nvim_practice.py

Press i, type or paste this, then press Esc:

def greet(name: str) -> str:
    return "Hello, " + name

print(greet("Hieu"))

Save with :w. Use a fresh filename if either practice file already exists.

Read something you don't understand

Use the arrow keys to move around if that's comfortable. You don't need fancy movement commands to use your language tools.

What you wantWhat to press
Find text in this file/, type the text, Enter. n goes to the next match.
Understand a function or variablePut the cursor on its name and press K (Shift+k) for documentation / type information.
See where it's definedOn its name, press gd.
See where it's usedOn its name, press gr. Pick a result just like the file picker.

For example: put the cursor on greet in the last line. Press gd to visit the function, then Ctrl o to return.

Your TypeScript language server supplies definitions, references, and type information. This also covers JavaScript and TSX files.

Pyright supplies Python definitions, references, and type information. Imports work best when the project's Python environment and dependencies are available.

Make the change

You can start with i, type and delete normally, then Esc. These few actions make common edits easier:

What you wantWhat to press
Replace a wordMove onto it, press ciw, type its replacement, then Esc.
Replace text inside double quotesMove inside the quotes, press ci", type the new text, then Esc. The quotes stay.
Add a line belowo (lowercase). It creates the line and lets you type. Finish with Esc.
Undo / redou / Ctrl r, after leaving typing mode.

For example: move inside "Hello, ", press ci", type Hey, , then Esc. Press u if you want the old greeting back.

Copy, paste, or comment a few lines
  • yy copies the current line. p pastes it below.
  • V selects a whole line. Move up/down to select more, then y to copy or d to cut. Paste with p.
  • gcc toggles a line comment. For selected lines, press gc.

Your clipboard is shared with macOS. Copying and cutting/deleting can replace its contents. Your custom Visual-mode p preserves the source text when pasting over a selection.

Let suggestions help you type

While you're in typing mode, start a variable or function name. Your completion menu should appear automatically.

  1. Use Ctrl n / Ctrl p to select a suggestion.
  2. Press Tab to accept it. In your setup, Enter is not the accept key.
  3. If the menu doesn't appear, try Ctrl Space. To dismiss it, use Ctrl e.

For example: on name in the return line, use ciw and type na. Choose the name suggestion, accept with Tab, then Esc.

This is blink.cmp using language-aware suggestions, not an AI agent. If Ctrl+Space switches your macOS input language instead, the OS intercepted the key.

Understand an error, or rename something

See a diagnostic marker or underline? Don't guess at what it means:

  1. Press ]d to move to the next diagnostic.
  2. Press Space d to read its message.
  3. Try Space ca for a suggested fix. If there isn't one, edit the code yourself. Available actions depend on the language server.

For example: greet(123) passes a number where the example expects a string. The language server should report that mismatch. Read the message, then change the argument back to "Hieu".

Renaming a function or variable? Put the cursor on its name, press Space rn, enter the new name, then Enter. The server can update references across files. Review the affected files with Space b; after checking them, :wa saves all modified files.

Diagnostics and rename need a working language server. Syntax colors alone don't tell you whether it's running.

Save, then review

Press Esc, type :w, then Enter. Your formatter runs on save, so you don't need a separate formatting shortcut.

For TypeScript / TSX, JavaScript / JSX, and JSON, your setup runs Prettier. It respects project configuration and prefers a project-local installation when available.

For Python, your setup runs Ruff's formatter. It respects project configuration. This does not mean Ruff linting or automatic lint fixes are enabled.

Formatting may change more lines than you edited. Check the result, then run your project's usual tests in another terminal pane. Saving does not run tests.

:q closes the current window and exits if it's the last one. It refuses to abandon unsaved changes.

When a coding agent made the changes
  1. Save your own edits before letting the agent change the same files.
  2. In the shell, use git diff to review unstaged changes, git diff --cached for staged changes, and git status --short to notice new files.
  3. Back in Neovim, run :checktime to check for external changes. Do not force a reload over your unsaved edits.
  4. Open touched files with Space f and use the same read/edit/save workflow above.
If something doesn't work

These are troubleshooting tools, not commands to run every session.

  • Definitions, rename, or errors missing: run :checkhealth vim.lsp. Your setup declares ts_ls for TypeScript/JavaScript and pyright for Python.
  • No formatting: run :ConformInfo to check formatter availability.
  • Tools not installed: :Mason shows installation status. Your config automatically installs the two language servers, Prettier, and Ruff. JS-based tools need Node.js/npm available.

That's the daily loop: find → read → edit → save. Pick up other commands when an actual task calls for them.
